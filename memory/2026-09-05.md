# 2026-09-05

Infra monitor was crying wolf; YFI (starter-yfi-h1-1) upgraded to an always-on watcher:

- `com.gotchibot.infra-monitor` had reported DEGRADED on 501 of 501 runs since
  Sep 3 — never once OK — while the stack was healthy the whole time. A real
  outage would have been indistinguishable from the noise.
- Cause 1: `checkDocker` used `containers.every(c => c.healthy)` over `docker ps -a`,
  so unrelated stopped containers (wondrstack-test-mongo, openclaw-gateway,
  gotchi-trader-postgres — all Exited 255 after a Docker restart, no restart
  policy) failed the whole check. Now only a WATCHED set of aarcade/envio
  containers gates it; a watched container that is missing entirely still fails.
- Cause 2: the local :8787 probe sent no `x-subgraph-proxy-key`, so
  services/subgraph-api-proxy/server.cjs answered 401 Unauthorized every time.
  The key is now read from SUBGRAPH_PROXY_SECRET or
  ~/Dev/AarcadeGh-t/services/subgraph-api-proxy/.env.
- New `scripts/infra-watch.mjs` runs resident in tmux `gotchibot:infrawatch`
  (60s ticks), reports transitions rather than steady state, writes a heartbeat
  to var/infra-watch/state.json, and every 30 ticks (plus on every transition)
  calls `scripts/infra-claude-verify.mjs` for an independent Claude CLI verdict.
  Probe/Claude disagreement raises `state.json.disagreement` — that is the check
  that would have caught the 501 false alarms immediately.
- `scripts/infra-watch-ensure.sh` + `com.gotchibot.infra-watch` (LaunchAgent,
  300s) restart the tmux window if it dies; idempotent.
- Environment trap: the Claude CLI (~/.local/bin/claude) reads OAuth from the
  login keychain, so `ssh imac 'claude -p …'` fails with
  "Not logged in · Please run /login". It only works inside tmux on the console
  session — hence the watcher lives in tmux, not a bare LaunchAgent. Likewise
  neither `docker` nor `claude` is on the non-interactive SSH PATH; use absolute
  paths.
