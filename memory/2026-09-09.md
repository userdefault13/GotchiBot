# 2026-09-09 — did LINK, WBTC and YFI actually run? (checked, then fixed)

## Findings
- **YFI**: fine. launchd supervisor loaded, resident watcher up since 09-06,
  all probes OK. Nothing to do; the pushed tree moved it to the 900 s interval.
- **LINK**: the 30-minute cycle was real (22 runs, exit 0) but every cycle stood
  down: the desk API reported `status: stale`. Root cause in Gotchi-Trader:
  `paperCronSummary.lastRunAt` was `MAX(paper_trades.created_at)`, i.e. the last
  *fill*, not the last *run*. The 09-08 paper cron completed with zero fills, so
  it counted as no run. Fixed on the iMac (branch `fix/paper-desk-round-trips`):
  migration `015_paper_cron_runs.sql` adds a heartbeat table,
  `scripts/cron-paper-daily.ts` writes a row per run, and both summary paths take
  the newest of last fill / last gameplan open / last completed run. API
  restarted via `launchctl kickstart -k gui/$UID/com.gotchi-trader.api`. The desk
  turns healthy after the next 14:00 PDT paper run.
- **WBTC**: never ran. The iMac crontab pointed at
  `scripts/comms-agent-cron-run.sh`, which did not exist there (both nightly
  firings logged "No such file or directory"). The 09-08 deploy had never
  reached the iMac. Fixed with `./scripts/gotchibot comms schedule install` from
  the MBP after `remote-push`; status now reports wrapper ok, `50 23 * * *`.

## Things learned about the tooling
- `remote-push` rsyncs with `--delete` and the MBP has no `sessions/trader-logs`
  or `sessions/infra-logs`, so it would have deleted LINK's and YFI's logs on the
  iMac. Those dirs (and `sessions/c2*/`) are now excluded, and
  `REMOTE_PUSH_DRY_RUN=1` prints an itemised dry run first.
- Any `./scripts/gotchibot …` run on the iMac **over SSH** fails: the wrapper
  calls `abra run`, and the iMac keychain refuses non-interactive access
  ("User interaction is not allowed"). Run status commands from the MBP, or
  inside the iMac's `gotchibot` tmux session (GUI login, keychain OK).
- abra on the iMac was a stale non-git 0.1.0 snapshot with no LAN sync. The
  published 1.0.2 tarball was broken (postinstall + Swift helper source not in
  `files`); fixed and published as 1.0.3, installed on the iMac, vault synced
  over Tailscale (`abra usb host` on the MBP needs Touch ID; the iMac side needs
  someone at its screen to approve its own auth dialog).
